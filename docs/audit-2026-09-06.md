# GROTEC FarmerOS Audit

Read-only audit against PRD v2.1 and Developer Requirement Brief v1.0.

---

## 1. Architecture Overview

React + Vite SPA -> REST /api/v1 -> NestJS monolith -> PostgreSQL via Prisma.

Identity: single `employees` table (no CRM-only user table).
Roles: FOUNDER / MANAGER / AGENT / STAFF.
RBAC: RolePermission + PermissionGuard + RequirePermission decorator.
Auth: JWT access token (15 min) + rotating refresh token (httpOnly, hashed, session-bound).

External integrations behind internal abstractions:
- AutoDialerProvider (mock + config-selected vendor)
- MessagingProvider (mock + config-selected vendor)
- OpenAiCompatibleLlmProvider (env-configurable)

## 2. CRM Modules (implemented)

- Farmer master: farmer_code, phones (E.164, partial unique index), locations (village/taluk/district/state/pincode), customer_crops junction
- Leads: lead_ownership (append-only, one active owner)
- Calls: calls + call_notes, 6 canonical call states, one-active-call-per-agent 409
- Outcomes: INTERESTED / NOT_INTERESTED / NOT_ANSWERED, outcome and next_action separate columns
- Relationship ownership: relationship_ownership (append-only, one active RM)
- Knowledge Base: crop_product_guidance, browsable page + AI Assistant chat
- Dashboard: role-scoped live aggregates

## 3. HRMS Modules (implemented)

- HRMS Dashboard, Employee Management, Employee Profile
- Attendance: mark/bulk/correct/approve/reject, ESSL webhook + sync
- Leave: types, balances, applications, approve/reject
- Payroll: IDLE -> GENERATED -> APPROVED_LOCKED -> PUBLISHED state machine
- KPI: team scorecard, personal scorecard, freeze, target config
- Employee History: training/warning/commendation/promotion

## 4. Gaps vs PRD

PRD Phase 1 = CRM + HRMS + ESSL. CRM and HRMS are implemented. ESSL is webhook-only (no device connector, no TCP/IP pull daemon).

## 5. Gaps vs Developer Brief

Brief 90-day V1 adds Sales, Inventory, Accounts, WhatsApp, full AI, Data Migration. None exist.

## 6. Critical Weaknesses

1. AI Assistant scope change not formally approved (PRD says Phase 3, project implemented Phase 1)
2. No background job queue (Brief 12 requires queues)
3. No data export implementation (Brief 14 requires controlled+logged exports)
4. No monitoring/APM (Brief 12 requires it)
5. Farmer classification only ACTIVE/INACTIVE (Brief 5 requires 4 states)
6. Lead status only OPEN/CLOSED (Brief 7 requires 9-stage ladder)
7. Bulk Excel import not built
8. No migration/reconciliation tooling

## 7. Verdict

CRM architecture is well-executed and largely PRD-compliant. HRMS is fully implemented. Three structural gaps remain: no background job queue, no data export, no monitoring/APM. AI Assistant scope change needs formal GROTEC sign-off.
